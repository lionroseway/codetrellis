CodeTrellis 0.3.1 makes rules see every import, in Python, Rust, C#, PHP, TypeScript and JavaScript, and brings the app and the phone companion up to date underneath: a newer Electron and Chromium, a newer WebRTC engine on both ends of the phone link, and no known advisory in anything either one ships. A rule that looked clean may have been missing most of what breaks it, so read the first section if you use a baseline.

## ⚠️ Before you start

- **Using `.codetrellis/rules/baseline.yaml`? Do this before you move CI to 0.3.1.** 0.3.0 read only the top level of a Python, Rust or C# file, and only the `import` statements of a TypeScript or JavaScript one. 0.3.1 also sees a Python import inside a function, a `try:`, an `if` or under `if TYPE_CHECKING:`, a Rust `use` inside a `fn` or a `mod tests { }`, a C# `using` inside a namespace or an `#if`, `require('x')` and `import('x')`, and a PHP `use A\{B, C}`, `use function` or `use const`. So a baseline written by 0.3.0 can list too few, and every check then fails with `… and its baseline does not list it`, on any change. `codetrellis rules baseline` will not add them, because a baseline only shrinks.
  1. While CI is still on 0.3.0, remove the affected rules from `baseline.yaml` in a pull request. Its check passes there.
  2. Once that has merged, run `codetrellis rules baseline` on 0.3.1 and commit the result, then move CI to 0.3.1.

  If CI has already moved, that first pull request fails its own check and has to be merged over it.
- **No baseline?** Nothing to do. The check judges only what a change adds, so existing code does not start failing. The Rules view will show the breaches it was missing.
- **The phone companion is 0.3.1 too.** Pairing is unchanged, so there is no re-pairing. **Android:** install `CodeTrellis-Companion-0.3.1.apk`, attached below. **iOS:** TestFlight <!-- TODO build number -->. Update it with the desktop: the new companion is what finds a desktop on iOS's current network discovery, and what drops one from the list when it leaves.

## 📏 Rules

- **Rust, C#, TypeScript and JavaScript package rules no longer under-report.** A `use` inside a function or a test module and a `using` inside a namespace or an `#if` now count. So do `require('x')` and `import('x')`, which load a module as surely as `import` does, when the name is written out. `pub use stripe::X` now counts as the crate `stripe`, where 0.3.0 read it as a crate called `pub use stripe`. The rules guide lists what each language counts and what it deliberately does not.
- **PHP rules read every form of `use`.** A group like `use Stripe\{Charge, Refund}` was dropped, and now counts as each member. `use function` and `use const` were read as a package whose name began with the keyword. A rule about a named class now also sees it when the file imports it under an alias.
- **Python package rules no longer under-report.** A rule now finds an import wherever in the file it is. On one real repository, a rule that recorded 30 files now finds all 57. Rules about who may import a file or a named export see these imports too, and they appear as edges on the graph.
- **Write a Python package the way pip does or the way the code does.** `pypi:langchain-ollama` and `pypi:langchain_ollama` are now one package, and case does not matter. Before, the hyphenated spelling matched nothing and said nothing. A distribution whose module has another name is still named by its module: `pypi:yaml` for PyYAML.
- **One file the parser cannot finish no longer costs the project its graph.** A deeply nested file, the kind code generators write, could end the scan's whole parsing pass, leaving every file with no symbols or imports and the rules with nothing to read. Now that file loses only what could not be read, and its imports are still read.
- **A check no longer passes on code it could not read.** If a scan fails, `codetrellis check` now fails (exit 3) while any rule blocks, and says why. Before, it reported that the rules were not checked and exited 0. `start` says a failed scan on stderr, and `scan` exits 1.
- **Your machine and CI now agree straight after an upgrade.** The first scan on a new version parses every file again, so a machine that had already scanned no longer keeps the old answer for files that have not changed.

## 📱 Phone

- **A desktop that leaves the network now leaves the list.** The companion listened for the wrong event from its discovery library, so a desktop that quit or moved networks stayed on the device list until the app restarted.
- **Discovery on iOS uses the system's own service browser,** and the app now declares the `_codetrellis._tcp` service it looks for, as iOS requires.
- **A newer WebRTC engine** (libwebrtc M155) and Expo SDK 58 with React Native 0.88 underneath. Nothing about pairing or the four channels changes.

## 🖥 Desktop

- **Electron 45,** with the Chromium and Node that come with it. The database driver moves with it, as it must, and an existing database opens as before.
- **The peer link's WebRTC library is current.** The 1024-byte limit on each piece of a message, which keeps the phone link working through a VPN, used to be a patch to the library and is now one of its settings, checked by a test that inspects the pieces actually sent.
- **Eleven packages nothing used are gone** from the install.

## 🔒 Security

- **No known advisory in anything the desktop or the phone ships.** Every lockfile audits clean, development and build tooling included, among them the advisories published since 0.3.0 against an HTML sanitiser, a schema validator and a request parser the desktop uses.
- **Electron is now audited on every change.** It is a development dependency, which the blocking audit skipped even though it ships inside the app. It has a blocking check of its own now.

## Known limits

- **Breakpoints detect and report a write that got past them; they don't undo it.**
- **Google Drive and Dropbox shared folders aren't detected** as shared plans folders. OneDrive and SharePoint are.
- **Windows portable `.exe`:** an agent's connection starts only while CodeTrellis is open, and must be re-added after each update. Use the Windows installer for agent work.
- **Linux AppImage** runs without Chromium's sandbox. Prefer the `.deb` or `.rpm` where you have the choice.
- **Windows** builds aren't code-signed, so SmartScreen may warn once.

## First launch

- **macOS:** drag to Applications and open. If you see "app is damaged" (usually because the download lost its attributes), run `xattr -cr /Applications/CodeTrellis.app` once.
- **Windows:** SmartScreen may warn once. Choose "More info", then "Run anyway".
- **Linux (AppImage):** `chmod +x CodeTrellis-0.3.1-x86_64.AppImage && ./CodeTrellis-0.3.1-x86_64.AppImage`
- **Linux (.deb / .rpm):** `sudo apt install ./codetrellis_*.deb` or `sudo dnf install ./codetrellis-*.rpm`
