CodeTrellis 0.3.0 is the rules release. A repository can now write down how its code is meant to be built, which packages go through which wrapper, which layers may not import which, and what text must never appear, and have that checked anywhere: on your machine, in an agent's session, and on every pull request, with no AI and no secret needed. Agents can propose rules but only a person can make or loosen one. The CLI is on npm, and the app carries it too.

Coming from 0.1.x? The [0.2.0](https://github.com/lionroseway/codetrellis-releases/releases/tag/v0.2.0) and [0.1.18](https://github.com/lionroseway/codetrellis-releases/releases/tag/v0.1.18) notes describe lines of work, overlaps, breakpoints, replay and the record, which this version builds on.

## ⚠️ Before you start

- **The app offers, once, to add the `codetrellis` command** to your terminal (on macOS it links `/usr/local/bin/codetrellis` and asks for your password). Say yes if you want `codetrellis check` and the agent verbs from any shell. Settings → MCP Server → Command line adds or removes it later.
- **For CI and servers, the CLI is on npm:** `npx codetrellis` or `npm i -g codetrellis`. It needs no desktop app, and its version matches this release.
- **Rules you set in 0.1.18–0.2.0 still count.** They lived in `.codetrellis/config.json`. The new Rules view shows them and offers to move them to `.codetrellis/rules/`, where they are reviewed like code. Nothing moves until you choose to.
- **The phone companion is 0.3.0 too,** and pairing is unchanged since 0.1.14, so there is no re-pairing. **Android:** install `CodeTrellis-Companion-0.3.0.apk`, attached below. **iOS:** TestFlight build 29. An older companion keeps working with this desktop, without the new "Needs you" findings.

## 📏 Rules

- **A rulebook in the repository.** Rules are YAML in `.codetrellis/rules/<suite>.yaml`, committed with the code and owned like code. A rule can say:
  - who may import what;
  - that only one wrapper may import a package such as `stripe`, in any of the eleven languages;
  - who may import a named export, followed through re-exports;
  - who may call an HTTP host, touch a table, run a command or read an environment variable;
  - what the files in a folder must be;
  - what text must, or must not, appear.
- **Fuzzy and pattern matching.** A target can match by glob, regex or look-alike name, so a typo-squatted package or a near-duplicate is caught. You can teach it your own kinds of call (a queue, an event, a feature flag) without writing code.
- **Strength you choose.** `block` fails the check, `warn` says so and passes, `guide` only shows wherever the work touches it. New rules start at warn. Breaches that already exist are counted in a baseline that may only shrink, so a rule can land on old code without blocking everyone.
- **Only a person changes a rule.**
  - Agents propose with `propose_rule` and say why; you accept or reject in the app.
  - Every change shows its effect on the code before you make it.
  - Loosening a rule needs your signature, and a pull request can't bring the key that approves it.
- **The Rules view** has its own workspace: each rule with what breaks it today, the proposals waiting on you, and the move from `config.json`. The graph draws breaches, and selecting a file lists the rules that apply to it.
- **Rules reach the agent.** A task's brief, the overlap card and the awareness digest name the rules in scope, so an agent hears about a rule before it breaks it.

## ✅ Checks anywhere

- **`codetrellis check`** answers "does this change conform?" in a terminal, a session hook or any CI. It exits non-zero when the change breaks a blocking rule, when its tests fail or are older than the code, when a done task fails its checks, or when a doc describing it is stale. Narrow it with `--suite`, `--rule` or `--path`. Output can be SARIF for any code host.
- **Agent checks on your own agent.** An agent reviews the change against the rules in scope, on your agent, model and key: Claude Code, Codex, Cursor, or any MCP client. CodeTrellis supplies the bundle and checks what comes back.
  - Every finding must quote lines it was actually shown, and is dropped if it doesn't.
  - Files named like secrets are never sent.
  - An instruction hidden in the change is flagged, not followed.
- **A review run on your device counts on the pull request.** It is signed with your device key and verified in CI against the keys your base branch lists. CI needs no secret to trust it.
- **Agent checks in CI too,** on your provider's key, with a cost limit, and an optional second pass that verifies the first.
- **Check runs travel with the repository.** Each run is kept in `.codetrellis/runs/checks/`, so a run made on a laptop, in CI or by an agent shows up in the app beside the others.
- **Pipelines.** Checks can run in stages, in order or in parallel, and a later stage can build on what earlier ones found.
- **The Checks view.** Run any check from the app and see CI's runs beside your own. Comparing two runs shows what got fixed and what is new.
- **Findings where the code is.** What the latest check found shows on the importing line in the code view, the diff and the inspector, in a task's brief, and on the phone's "Needs you". A repeated finding can graduate into a proposed rule.
- **Reviews in order of risk.** A review opens with what the change does to the architecture, sorted by dependents, rule scope and test coverage. Each reviewer sees only what changed since they last looked.

## 💻 CLI

- **On npm as `codetrellis`.** It is published from CI with npm's trusted publishing, so no npm token exists anywhere.
- **Carried by the app,** running on the app's own binary, so you don't need Node.
- **`codetrellis desktop install`** downloads the app and checks it against the same signed checksums the updater uses before opening it.

## 🖥 Desktop

- **The graph has a legend and one visual language.** Colours, glyphs, dashes and words mean the same thing on the graph, the plan canvas, the file tree and the Timeline.
  - Edge toggles show or hide imports, cross-system calls and symbol links.
  - The graph goes full screen and back.
  - Hidden panes leave no gap.
- **Selecting a file lists the plans and tasks that touch it.**
- **The branch popover scrolls and searches,** even with sixty branches, and keeps worktrees in view. Each worktree says where it is, and one inside the project is no longer scanned as part of it.
- **Quiet under load.** A `git pull` that touches many plans now reloads each plan once, with one notice, instead of a storm of refreshes and toasts. Large checkouts with many worktrees list their lines of work in one shared pass, and the graph no longer waits behind it.
- **Smaller fixes:**
  - Long plan names and headings fit.
  - Opening a plan from a chip always shows it.
  - Escape from a ticked checkbox now minimises the plan workspace.

## 📚 Docs

- **Every building block has a worked example,** in `docs/claude/rules.md` in the source repository, and each example runs as a test, so the docs can't drift from what the app does. Pipeline recipes for any CI are alongside.

## 📱 Phone

- **"Needs you" shows what the latest rule check found** next to the work it affects.

## 🔒 Security

- **Dependency advisories fixed:** shell-quote (critical), source-map-js and http-cache-semantics, in both the desktop and phone builds. The npm package installs with none.
- **Rule approvals are checked against the base branch's signers** even when a project is opened through a symbolic link.

## Known limits

- **Breakpoints detect and report a write that got past them; they don't undo it.**
- **Google Drive and Dropbox shared folders aren't detected** as shared plans folders. OneDrive and SharePoint are.
- **Windows portable `.exe`:** an agent's connection starts only while CodeTrellis is open, and must be re-added after each update. Use the Windows installer for agent work.
- **Linux AppImage** runs without Chromium's sandbox. Prefer the `.deb` or `.rpm` where you have the choice.
- **Windows** builds aren't code-signed, so SmartScreen may warn once.

## First launch

- **macOS:** drag to Applications and open. If you see "app is damaged" (usually because the download lost its attributes), run `xattr -cr /Applications/CodeTrellis.app` once.
- **Windows:** SmartScreen may warn once. Choose "More info", then "Run anyway".
- **Linux (AppImage):** `chmod +x CodeTrellis-0.3.0-x86_64.AppImage && ./CodeTrellis-0.3.0-x86_64.AppImage`
- **Linux (.deb / .rpm):** `sudo apt install ./codetrellis_*.deb` or `sudo dnf install ./codetrellis-*.rpm`
