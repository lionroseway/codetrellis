# Release notes plan — the release after 0.1.17 (Phase 32)

A plan, not the notes. The notes are written from it once the build in the
runbook (`docs/releases/RUNBOOK.md`) has passed, as
`docs/releases/v0.1.18.md`, and published with `gh release edit`. Rules:
`.claude/skills/codetrellis-release-notes/SKILL.md`. Source range:
`0861ee8` (0.1.17) to the merge of Phase 32 into `main`.

## Version

**0.1.18** (the owner, 2 October). Phase 32 ships as 0.1.18; bugs found in
it are fixed and the features refined before 0.2.0. The notes say so
plainly, so people know to report what they hit.

## The one line

> CodeTrellis 0.1.18 watches every agent working on your code at once,
> across worktrees, branches and clones, tells them when their work
> collides before you have to, and keeps a record you can replay and prove.
> It is a large release: what you report is fixed, and the features
> refined, before 0.2.0.

## ⚠️ Before you start (what a reader must DO)

Check each against the build before it goes in.

- **Update the phone companion.** New screens: Needs you, overlaps with
  Acknowledge / Intended / Reply, breakpoints. **No re-pairing**: pairing has
  not changed since 0.1.14. Name the APK and the TestFlight build attached.
- **Nothing new reaches the network unless you turn it on.** Keeping remotes
  current (Settings → Git) and review hosts (Settings → Review hosts) are
  off; each is a grant only you can make, in the window.
- **Optional: the Claude Code skill and hook, and a Gemini CLI hook**, so
  the agent checks its footprint and your breakpoints before it edits.
  Offered in Settings and written only when you click; nothing is installed
  for you.
- **Your record starts now.** The tamper-evident record begins at the first
  launch of this version. How long it is kept is Settings → Data → Record.
  (Check what the upgrade does to 0.1.17's existing history before writing
  this; the upgrade is a unit test, not seen on a real database yet.)

## What's new, by surface

Outcomes, not steps. Each bullet covers several steps.

### 🧭 Many agents at once (Tracks A, B)
- Every worktree, recent branch and clone is a line of work, in a strip
  in the top bar; any MCP agent (Claude Code, Codex, Cursor, …) is placed
  in the one it works in.
- When two lines of work change the same function, a contract others
  depend on, or drift off their ticket, the agents are told on their next
  step, and you see one line in Awareness. Mark it Intended and it stays quiet.
- Breakpoints: "ask me before touching payments". The agent's write waits
  for you, on the desktop or the phone.
- The Timeline survives a restart, with a lane per agent, its commits and
  its checks.
- Replay: the graph, the stack and what waited on you at any past moment;
  catch up at 4×.
- The Stack and Review tabs: what clashes (spreadsheets and documents too),
  and what to merge first, with reasons. The PR draft tells the story.
- Play-forward: where today's plans will collide before they do.

### 📋 Plans and teams (Track C)
- **Approve** a plan on its header or on the phone. An agent can ask for
  approval (it sets the plan to review) but cannot approve it.
- One plan across several worktrees.
- Team status through git, with any host or none; approvals signed with
  your git SSH key; the shared plans folder can be a git repo or a OneDrive
  / SharePoint folder.
- Skills on tasks; recurring playbooks, each run a fresh plan.
- Architecture rules, written once, kept by every agent and checked in CI.
- Tests tied to the code they cover: "done" on stale tests is caught.

### 🔎 How the code got here (Track E)
- With no plan at all: what changed where, any two points compared file by
  file and on the graph, a file's evolution, line history with the agent
  where known, and branches and pull requests through your own git and gh.

### 🧾 The record (B10)
- What was asked, done, checked and decided, in a hash chain; Settings
  says whether it is intact. Export evidence for any period as one signed
  page; anyone can verify it on their own CodeTrellis.

### 🖥 The CLI (Track D)
- `codetrellis` runs headless for an agent in a cloud session or a CI job:
  SessionStart hook and GitHub Actions recipes in `docs/recipes/`. Installed
  from a checkout for now (`npm ci && npm link`); a published package is
  planned.

### 📱 Phone (A4, B4.4)
- Needs you, overlaps in plain words, the lines of work, breakpoints to
  answer, and a push for anything high.

### 🛠 Reliability
- CodeTrellis no longer breaks your own `git commit` (its background reads
  took git's index lock).
- A clone with many branches no longer stalls the window.
- The Windows and Linux installers carry every library patch, checked on
  every build.

## Known limits (say them)

- Breakpoints detect and report a write that got past them; they do not
  undo it (K2, still open).
- Google Drive and Dropbox shared folders are not detected; OneDrive and
  SharePoint are.
- The CLI is installed from a checkout.
- Windows builds are not code-signed; SmartScreen warns once.
- AppImage runs without the Chromium sandbox; `.deb` / `.rpm` keep it.

## Found while building the demo, and fixed before 0.1.18

Each was found by `npm run demo` against the merged tree (2 October) and
fixed on the owner's word ("fix them now") before the build.

- **Approve a plan in the window or on the phone.** **Approve** is on the
  plan header and on the phone's plan screen; an agent sets "review" to ask,
  and `update_plan` refuses "approved".
- `line_history` asked about a line past the end of a file says so in
  words ("has 5 lines; line 40 is past its end").
- The evidence export, and the Timeline, say who decided a criterion:
  "You approved “…”", ", from the phone", or "Someone over the local API".
- A test report written again by a later run, byte for byte, counts as a
  new run from when it ran; the same file handed over twice still does not.
- An agent's line of work is watched from the moment it connects, so with no
  window open the agent beside it is still told of an overlap.
- Two harness runs of the same tests on one checkout no longer wipe each
  other's folders.

Still to watch: `e2e/agent/mcp-ui-tools.spec.ts`'s first test failed once
and passed on the re-run.

After 0.1.18: a signal refresh runs git and parsing on the backend's one
thread, so a person's answer (Acknowledge, say) can wait seconds behind one
when files are changing fast. Found when `brief-other-work` stalled on CI
beside a spec writing into the same project (#328). Move that work off the
request path.
