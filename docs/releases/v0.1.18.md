CodeTrellis 0.1.18 watches every agent working on your code at once, across worktrees, branches and clones, tells them when their work collides before you have to, and keeps a record you can replay and prove. It is a large release. What you report is fixed, and the features refined, before 0.2.0, so please tell us what you hit.

## ⚠️ Before you start

- **Update the phone companion** for the new screens: Needs you, overlaps, breakpoints. No re-pairing: pairing hasn't changed since 0.1.14. **Android:** `CodeTrellis-Companion-0.1.18.apk` is attached below; install it over the old one. **iOS:** build 28 has been submitted to TestFlight (invite-only) and shows up there once Apple finishes processing it.
- **Only you approve a plan.** **Approve** is on the plan header and on the phone's plan screen. An agent can ask for approval by setting the plan to review, but an agent's `update_plan` that sets it to approved is now refused, and nothing else in that call is applied. If your agent's instructions told it to approve its own plan, change them.
- **Nothing new reaches the network unless you turn it on.** Keeping remotes current (Settings → Git) and review hosts (Settings → Review hosts) are off. Each is a grant only you can make, from the CodeTrellis window.
- **Optional: the Claude Code skill and hook, and a Gemini CLI hook,** so the agent checks what its edit overlaps and asks about your breakpoints before it writes. They're offered in Settings and written only when you click. Nothing is installed for you.
- **Your record starts now.** The tamper-evident record of what agents asked, did, checked and decided begins at the first launch of this version. Your plans and history from 0.1.17 are untouched. How long the record is kept is Settings → Data → Record.

## 🧭 Many agents at once

- **Every worktree, recent branch and clone is a line of work,** shown in a strip in the top bar. Any MCP agent (Claude Code, Codex, Cursor, …) is placed in the line it works in.
- **Agents are told when their work collides.** When two lines of work change the same function or a contract others depend on, or drift off their ticket, each agent hears about it on its next step, and you see one line in Awareness. Mark it Intended and it stays quiet.
- **Breakpoints:** "ask me before touching payments". The agent's write waits for you, on the desktop or the phone.
- **The Timeline survives a restart,** with a lane per agent, its commits and its checks.
- **Replay** shows the graph, the stack and what waited on you at any past moment. Catch up at 4×.
- **The Stack and Review tabs** show what clashes (spreadsheets and documents too) and what to merge first, with reasons. The PR draft tells the story of the work.
- **Play-forward** shows where today's plans will collide before they do.

## 📋 Plans and teams

- **Approve a plan yourself,** on its header or on the phone, as above.
- **One plan across several worktrees.**
- **Team status through git,** with any host or none. Approvals are signed with your git SSH key. The shared plans folder can be a git repo or a OneDrive / SharePoint folder.
- **Skills on tasks, and recurring playbooks** where each run is a fresh plan.
- **Architecture rules,** written once, kept by every agent and checked in CI.
- **Tests tied to the code they cover,** so "done" on tests older than the code is caught.

## 🔎 How the code got here

- **With no plan at all:** what changed where, any two points compared file by file and on the graph, a file's evolution, line history with the agent where it's known, and branches and pull requests through your own git and `gh`.

## 🧾 The record

- **What was asked, done, checked and decided, in a hash chain.** Settings says whether it's intact. Export evidence for any period as one signed page, and anyone can verify it on their own CodeTrellis.
- **Each decision says who made it:** "You approved", "from the phone", or "Someone over the local API".
- **Changes over the local API can be refused.** Settings → MCP Server → Local API turns off every change that doesn't come from the app window, an agent's MCP connection or your phone. Changes that arrive that way are tagged "unverified" wherever they show.

## 🖥 The command line

- **`codetrellis` runs headless** for an agent in a cloud session or a CI job, with SessionStart hook and GitHub Actions recipes in `docs/recipes/`. For now it's installed from a checkout (`npm ci && npm link`). A published package is planned.

## 📱 Phone

- **Needs you,** overlaps in plain words with Acknowledge / Intended / Reply, the lines of work, breakpoints to answer, and a push for anything high.
- **Approve a plan** from its plan screen.
- **Recurring playbooks** can be run from the phone.

## 🛠 Reliability

- **A project with an iOS or Android app in it no longer stops CodeTrellis seeing your lines of work.** Watching each line of work used to hold a file open for everything under it, `ios/Pods` included, until git itself could no longer start, and lines of work, overlaps and line history went quietly empty.
- **A project opened through a link, or inside a hidden folder, works like any other.** On macOS `/tmp` is a link, so a project there was named two ways and the window couldn't answer an overlap an agent raised; a project under a folder like `~/.config` was never watched for changes.
- **CodeTrellis no longer breaks your own `git commit`.** Its background reads used to take git's index lock.
- **Working out who overlaps with whom no longer holds up the app.** Git runs without blocking, one refresh runs per project at a time, and your answer to an overlap is applied at once instead of waiting seconds while files change fast.
- **A clone with many branches no longer stalls the window.**
- **An agent's line of work is watched from the moment it connects,** so the agent beside it is told of an overlap even with no window open.
- **The update download shows its progress and asks where to save.**
- **The Windows and Linux installers carry every library patch,** checked on every build.
- Smaller things: resizing a terminal as it closes no longer raises an error; an empty graph scans its own project instead of showing an error; the graph refits when the layout changes; a project removed from Recents stays removed; a new plan opens straight away; `line_history` on a line past the end of a file says so in words; a test report written again by a later run counts as a new run.

## Known limits

- **Breakpoints detect and report a write that got past them; they don't undo it.**
- **On macOS, watching uses one file handle per source file.** Dependencies, build output and `ios/Pods` are skipped, so a typical repository costs a few thousand. A repository with more than about 20,000 source files in one line of work can still run out; a watcher that costs one handle per folder tree is planned.
- **Google Drive and Dropbox shared folders aren't detected** as shared plans folders. OneDrive and SharePoint are.
- **The CLI is installed from a checkout.**
- **Windows portable `.exe`:** an agent's connection starts only while CodeTrellis is open, and must be re-added after each update. Use the Windows installer for agent work.
- **Linux AppImage** runs without Chromium's sandbox. Prefer the `.deb` or `.rpm` where you have the choice.
- **Windows** builds aren't code-signed, so SmartScreen may warn once.

## First launch

- **macOS:** drag to Applications and open. If you see "app is damaged" (usually because the download lost its attributes), run `xattr -cr /Applications/CodeTrellis.app` once.
- **Windows:** SmartScreen may warn once. Choose "More info", then "Run anyway".
- **Linux (AppImage):** `chmod +x CodeTrellis-0.1.18-x86_64.AppImage && ./CodeTrellis-0.1.18-x86_64.AppImage`
- **Linux (.deb / .rpm):** `sudo apt install ./codetrellis_*.deb` or `sudo dnf install ./codetrellis-*.rpm`
