CodeTrellis 0.2.0 rounds off the many-agents work that arrived in [0.1.18](https://github.com/lionroseway/codetrellis-releases/releases/tag/v0.1.18): what you reported, and what we found running it on real repositories, is fixed. Large repositories stay responsive, open plans keep up with agents as they work, and a task shows the rules it inherits. Desktop only: the phone companion is unchanged.

Coming from 0.1.17 or earlier? The [0.1.18 notes](https://github.com/lionroseway/codetrellis-releases/releases/tag/v0.1.18) describe lines of work, overlaps, breakpoints, replay, the record and the rest of what this version builds on.

## ⚠️ Before you start

- **The phone companion stays at 0.1.18.** Nothing in this release touches it, and pairing hasn't changed since 0.1.14. **Android:** keep `CodeTrellis-Companion-0.1.18.apk`, attached to [v0.1.18](https://github.com/lionroseway/codetrellis-releases/releases/tag/v0.1.18). **iOS:** TestFlight build 28.

## 🧭 Plans and agents

- **Open plans follow agents live.** When an agent claims a task, moves it on or logs activity, a plan you have open shows it straight away, with no reload.
- **A task shows the rules it inherits.** Claim policy ("Human only"), model and guardrails set on a parent now show on each task beneath it as "(inherited from …)", even if you never opened the parent. Agents were always held to them; the window used to show "Anyone (default)".
- **Any branch can be given a section of a plan,** not only a branch with recent unmerged work.
- **Long plan titles wrap** instead of being cut off.

## 🛠 Reliability

- **Claiming a task answers at once on a repository with hundreds of branches.** Agents' claims, "next item" and the brief used to wait for a full pass over every line of work, which took over 30 seconds on a large repository, longer than an agent waits, so the claim never landed. They now ask only what they need.
- **Pinning a baseline or scanning no longer freezes the app.** On a large project every other request, yours and the agents', used to wait while the files were stored: up to 11 seconds on 2,500 files. The app now keeps answering throughout, and pinning stores only what changed.
- **A skill added before it was committed learns who added it** once the commit lands, instead of staying "not committed yet" for good.
- **Opening a project while another project is still being scanned now opens it** once that scan finishes, instead of quietly doing nothing.

## Known limits

- **Breakpoints detect and report a write that got past them; they don't undo it.**
- **Google Drive and Dropbox shared folders aren't detected** as shared plans folders. OneDrive and SharePoint are.
- **The CLI is installed from a checkout.**
- **Windows portable `.exe`:** an agent's connection starts only while CodeTrellis is open, and must be re-added after each update. Use the Windows installer for agent work.
- **Linux AppImage** runs without Chromium's sandbox. Prefer the `.deb` or `.rpm` where you have the choice.
- **Windows** builds aren't code-signed, so SmartScreen may warn once.

## First launch

- **macOS:** drag to Applications and open. If you see "app is damaged" (usually because the download lost its attributes), run `xattr -cr /Applications/CodeTrellis.app` once.
- **Windows:** SmartScreen may warn once. Choose "More info", then "Run anyway".
- **Linux (AppImage):** `chmod +x CodeTrellis-0.2.0-x86_64.AppImage && ./CodeTrellis-0.2.0-x86_64.AppImage`
- **Linux (.deb / .rpm):** `sudo apt install ./codetrellis_*.deb` or `sudo dnf install ./codetrellis-*.rpm`
